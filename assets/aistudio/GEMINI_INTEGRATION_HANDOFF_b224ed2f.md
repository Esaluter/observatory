# NASA Observatory — Gemini Integration Handoff

This document is the data contract for connecting the immutable Collector release to the
existing React + TypeScript + Vite Observatory. Do not infer publishing rights from NASA
branding, host names, or missing copyright fields. The Collector has already made the
component-level decision exposed in each public item.

## 1. Entry point and manifest

Load the single mutable pointer:

```text
<Vite base>/data/manifest.json
```

The manifest remains `schemaVersion: 1` and points to one immutable release:

```json
{
  "schemaVersion": 1,
  "releaseId": "<content-derived id>",
  "sources": {
    "apod": {
      "index": "releases/<releaseId>/apod/index.json",
      "count": 2,
      "candidateCount": 82,
      "safeStubCount": 80,
      "cards": {"full": 0, "mediaOnly": 2, "textAiSummary": 0}
    },
    "epic": {
      "index": "releases/<releaseId>/epic/index.json",
      "collections": {
        "natural": "releases/<releaseId>/epic/natural/index.json",
        "enhanced": "releases/<releaseId>/epic/enhanced/index.json"
      }
    },
    "library": {"index": "releases/<releaseId>/library/index.json"}
  },
  "cards": {"full": 74, "mediaOnly": 2, "textAiSummary": 0},
  "checksums": {"releases/<releaseId>/...": "sha256"}
}
```

Index paths in `manifest.sources.*.index` are relative to `data/`, not to the application
root. Load them as `<Vite base>/data/${index}`.

## 2. Index shape

Every source index has the backward-compatible structure:

```json
{
  "schemaVersion": 1,
  "source": "apod | epic | library",
  "generatedAt": "ISO-8601",
  "items": [],
  "safeStubs": []
}
```

Render `items` as publishable cards. Treat `safeStubs` as references only; they deliberately
exclude titles, descriptions and local media.

## 3. Card types

### Full Card

`cardType: "full"`, `contentType: "source_text"`.

```json
{
  "id": "epic:natural:...",
  "cardType": "full",
  "title": "...",
  "date": "...",
  "description": "...",
  "localMediaUrl": "data/releases/<releaseId>/media/epic/...jpg",
  "sourceUrl": "https://epic.gsfc.nasa.gov/",
  "attribution": "NASA EPIC Team",
  "rights": {
    "media": {"status": "approved", "policyUrl": "https://epic.gsfc.nasa.gov/about"},
    "text": {"status": "approved"}
  }
}
```

Render the media and source description. Display attribution and a source link.

### Media-only Card

`cardType: "media_only"`. Media is approved, but the original APOD explanation is not.

```json
{
  "id": "apod:2026-09-05",
  "cardType": "media_only",
  "contentType": "metadata",
  "title": "...",
  "date": "2026-09-05",
  "description": "Safe factual metadata generated by Collector; not the APOD explanation.",
  "localMediaUrl": "data/releases/<releaseId>/media/apod/...jpg",
  "sourceUrl": "https://science.nasa.gov/...",
  "attribution": "NASA",
  "rights": {
    "media": {"status": "approved"},
    "text": {"status": "review_required"}
  }
}
```

Do not recover, scrape or display the original APOD explanation. If an `aiSummary` field is
present, it has passed editorial approval and may be displayed as independent content.

### Text / AI Summary Card

`cardType: "text_ai_summary"`, `contentType: "ai_summary"`.

```json
{
  "id": "apod:...",
  "cardType": "text_ai_summary",
  "mediaType": "none",
  "mediaUrl": null,
  "localMediaUrl": null,
  "title": "Independent Russian explanation",
  "description": "...",
  "aiSummary": {
    "contentType": "ai_summary",
    "language": "ru",
    "title": "...",
    "body": "...",
    "factSources": ["https://..."],
    "reviewStatus": "approved",
    "disclosure": {
      "ru": "Объяснение подготовлено с помощью ИИ на основе научных источников. Не является официальным переводом NASA.",
      "en": "Explanation prepared with AI assistance using scientific sources. This is not an official NASA translation."
    }
  }
}
```

Never render local or remote media for this card type unless a later release explicitly
changes the card to `media_only` or `full` with `rights.media.status: "approved"`.

## 4. Media URLs and Vite base

`localMediaUrl` is relative to the site base and already includes `data/releases/...`.
Resolve it without adding a leading slash:

```ts
const publicUrl = `${import.meta.env.BASE_URL}${item.localMediaUrl.replace(/^\/+/, '')}`;
```

Use `localMediaUrl` when present. A media-only video may have `mediaStorageStatus:
"external_only"`; in that case use `mediaUrl` only because the item is already publishable
and its component media status is approved. Never use media URLs from `safeStubs`.

## 5. Safe stubs

A safe stub contains only identifiers, date, source URL, media type and rights state.

- It is not a gallery card.
- Do not infer a title or description from its source page.
- Do not load its remote media.
- It may be shown in a calendar as “available at source” with a link to `sourceUrl`.

## 6. Attribution and rights

- Display `attribution` near the media or description.
- Preserve `sourceUrl` as the original-publication link.
- `rightsEvidence` is audit information; it may be placed in an expandable details panel.
- Render a component only when its own `rights.<component>.status` is `approved`.
- `review_required` means insufficient evidence, not a confirmed prohibition.
- `restricted` must never be published.

## 7. RU / EN behavior

- EPIC source title and description are currently English.
- Approved AI Summary content is Russian and declares `language: "ru"`.
- Display the disclosure matching the active interface language; fall back to `disclosure.en`.
- Do not expose the 40 private GigaChat translations: they are intentionally absent from the
  public release.
- If no approved localized text exists, display the allowed source text or safe metadata; do
  not machine-translate in the browser.

## 8. NASA Library empty state

The Library index is valid when both `items` and `safeStubs` are empty. Render a normal empty
state such as “No reviewed Library materials in this release.” Do not treat this as a loading
failure.

## 9. Loading errors and fallback

1. Fetch `data/manifest.json` with cache revalidation.
2. Validate `schemaVersion === 1` and the required source descriptors.
3. Load source indexes independently so one failed source does not blank the whole site.
4. On an index failure, show a source-specific retry state and keep other sources visible.
5. On a missing local media file, show a neutral placeholder and the original source link.
6. Never fall back from a missing approved file to an unreviewed remote image.
7. Keep the last successfully loaded immutable release in memory during a refresh failure.

## 10. Security restrictions

- Do not fetch paths not listed by the manifest or source indexes.
- Reject paths containing `..`, backslashes or a foreign release ID.
- Never expose `.env`, credentials, tokens, private archive paths or translation registries.
- Do not derive approval from the `nasa.gov` domain, credits text, or the legacy
  `rightsStatus` alone; use `publicationStatus`, `cardType` and component rights.
- AI Summary drafts and `needs_review` records are never included in public `items`.
- Do not present the project as affiliated with or endorsed by NASA.

## 11. Recommended integration order

1. Add optional `cardType`, `contentType`, `rights`, `attribution`, `aiSummary` and
   `disclosure` fields to the existing TypeScript contract.
2. Keep all existing required APOD fields for backward compatibility.
3. Update the loader to resolve manifest-relative indexes and Vite-base media paths.
4. Add render branches for the three card types.
5. Add the safe-stub calendar/reference state.
6. Add the valid Library empty state.
7. Test a non-root Vite `base` and a failed source index.
8. Verify the active release ID shown by the UI matches `manifest.releaseId`.

The Collector owns rights decisions, immutable release creation, hashes and atomic manifest
switching. Gemini/Observatory owns presentation only and must not broaden publication rights.
